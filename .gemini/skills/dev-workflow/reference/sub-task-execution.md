# Sub-task Execution (TDD & Automation) Guide

이 문서는 서브에이전트가 개별 태스크(`task-XXX`)를 수행할 때 준수해야 할 기술적 절차와 규칙을 정의합니다.

## 서브에이전트 실행 사이클

서브에이전트는 메인 에이전트로부터 위임받은 태스크를 아래 TDD 사이클에 따라 독립적으로 완수해야 합니다.

### 1. Red (실패하는 테스트 작성)
- 구현하려는 기능의 명세(Input/Output)를 테스트 코드로 정의합니다.
- `tests/` 디렉토리의 적절한 위치에 테스트 파일을 생성하거나 추가합니다.
- `uv run pytest <test_file>`을 실행하여 해당 테스트가 실패하는지 확인합니다.

### 2. Green (기능 구현)
- 테스트를 통과하기 위한 최소한의 프로덕션 코드를 작성합니다.
- `GEMINI.md`의 규칙(한글 주석, `__init__.py` 사용 금지 등)을 엄격히 준수합니다.
- `uv run pytest <test_file>`을 실행하여 모든 테스트가 통과하는지 확인합니다.

### 3. Refactor (개선 및 문서화)
- 코드의 중복을 제거하고 가독성을 높입니다.
- Google 스타일의 Docstring(한글)을 작성하고 타입 힌트를 적용합니다.
- 리팩토링 후에도 테스트가 성공하는지 최종 확인합니다.

### 4. 검증 및 커밋 (Validation & Commit)
- `plan.md`에 명시된 검증 계획을 실행하여 기능적 무결성을 확인합니다.
- `commit-guide` 스킬을 활성화하여 변경 사항을 커밋합니다. (메시지 규칙 준수)

## 대량/반복 작업 지침
- 여러 파일에 걸친 반복 작업(예: 헤더 추가, 경로 수정) 시에도 동일한 '실행-검증-커밋' 흐름을 유지합니다.
- 작업 완료 후 샘플링 검증을 통해 전체적인 일관성을 확인합니다.

## 주의 사항
- **데이터베이스 격리**: 테스트 수행 시 반드시 인메모리 또는 분리된 테스트용 DB 파일을 사용해야 합니다.
- **도구 활용**: `eslint --fix`나 `prettier` 등 프로젝트 내 가용한 자동화 도구를 적극 활용합니다.

## 결과 보고 및 파일 저장 (Sub-agent to Main Agent)
태스크가 완료되면 서브에이전트는 메인 에이전트에게 결과를 보고함과 동시에, 해당 내용을 `work/task/<task-name>/task-<XXX>-result.md` 파일로 저장해야 합니다.

### 보고 및 저장 양식
1.  **태스크 완료 요약**: 수행한 작업 내용에 대한 간략한 요약
2.  **계획 대비 변경 사항**:
    - `plan.md`에 정의된 내용 중 수정되거나 생략된 부분이 있다면 그 이유와 함께 명시
3.  **테스트 결과**:
    - 자동화 테스트 실행 결과 (통과 여부, 실행된 테스트 파일명)
    - 실패한 테스트가 있다면 그 사유와 조치 결과
4.  **사용자 수동 확인 필요 항목**:
    - 자동화 테스트로 검증하기 어렵거나 사용자가 직접 브라우저/CLI에서 확인해야 할 항목
5.  **커밋 정보**: 생성된 커밋 메시지 및 해시 (반드시 포함)
