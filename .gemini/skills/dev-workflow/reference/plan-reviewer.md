# Plan Review Guidance

이 문서는 서브에이전트(예: `generalist`)를 호출하여 `plan.md`를 검토할 때 부여해야 할 역할과 규칙을 정의합니다.

## 서브에이전트 호출 방법
- **에이전트**: `generalist`
- **역할 부여**: "당신은 TDD와 클린 코드에 정통한 시니어 개발자이자 플랜 리뷰어입니다."

## 검토 기준
1.  **TDD 준수**: 모든 태스크가 Red -> Green -> Refactor 단계를 명시적으로 포함하는가?
2.  **완결성**: `requirement.md`에 정의된 요구사항을 모두 충족하는 계획인가?
3.  **현실성**: 서브 에이전트가 한 번의 턴으로 수행하기에 적절한 단위로 태스크가 나누어져 있는가?
4.  **검증 가능성**: `Validation Plan`이 구체적이고 실제 테스트 가능한 시나리오인가?

## 서브에이전트에게 전달할 프롬프트 구성
- 승인된 `requirement.md` 내용과 작성된 `plan.md` 내용
- 위 4가지 검토 기준에 따른 엄격한 검토 요청
- 프로젝트의 `GEMINI.md` 규칙(한글 주석 등)이 반영되었는지 확인 요청

## 보고 양식
서브에이전트는 검토 결과를 다음 형식을 준수하여 보고해야 합니다.

1.  **검토 요약**: 플랜의 전반적인 논리적 흐름과 TDD 프로세스 준수 여부에 대한 종합 의견
2.  **검토 항목별 상세 의견**:
    *   **TDD 준수**: Red/Green/Refactor 단계가 명확하고 적절하게 정의되었는가?
    *   **완결성**: `requirement.md`의 모든 요구사항이 태스크에 반영되었는가?
    *   **단위 적절성**: 각 태스크가 원자적(Atomic)이며 수행 가능한 크기인가?
    *   **검증 가능성**: `Validation Plan`이 구체적이고 신뢰할 수 있는가?
3.  **지적 사항 및 수정 권고**: 발견된 문제점과 이를 해결하기 위한 구체적인 수정 방향
4.  **최종 판정**: `[승인]` / `[보완 필요]` (보완 필요 시 사유 요약 포함)
