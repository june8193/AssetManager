# Task Execution (Sequential Delegation) Guide

`/dev-workflow run` 명령어 실행 시 메인 에이전트는 오케스트레이터 역할을 수행하며, 실제 구현은 서브에이전트에게 위임합니다.

## 실행 프로세스 (Main Agent)

1.  **계획 확인**: `work/task/<task-name>/plan.md` 파일을 읽어 전체 태스크 목록과 순서를 파악합니다.
2.  **순차적 위임**: `task-001`부터 순서대로 서브에이전트(예: `generalist`)를 호출하여 실행을 요청합니다.
    - **실행 지침**: 서브에이전트 호출 시 반드시 [sub-task-execution.md](sub-task-execution.md)의 지침을 프롬프트에 포함하거나 참조하도록 합니다.
    - **절대 금지**: 메인 에이전트는 직접 `write_file`, `replace` 등의 구현 도구를 호출해서는 안 됩니다.
3.  **결과 확인 및 진행**: 서브에이전트가 해당 태스크(TDD, 검증, 커밋 포함)를 완료하면 결과를 검토하고 다음 태스크로 넘어갑니다.
4.  **태스크 상태 업데이트**: 각 태스크가 완료될 때마다 `plan.md`의 체크리스트를 업데이트합니다.
5.  **최종 결과 보고서 작성**: 모든 태스크가 완료되면 각 태스크의 결과(`task-XXX-result.md`)를 취합하여 `work/task/<task-name>/result.md` 파일을 생성하고 사용자에게 최종 완료를 보고합니다.

## 최종 결과 보고서 양식 (`result.md`)
```markdown
# Final Implementation Report: <Task Name>

## 1. 전체 요약
- 구현된 주요 기능 및 변경 사항 총괄 요약

## 2. 태스크별 수행 결과
- **[task-001]**: 수행 요약, 커밋 해시, 테스트 결과
- **[task-002]**: ...

## 3. 계획 대비 변경 사항 (Total)
- 초기 `plan.md`와 실제 구현 간의 차이점 및 사유 취합

## 4. 검증 결과 및 확인 방법
- 전체 테스트 통과 여부 및 사용자가 직접 확인해야 할 기능/경로 안내

## 5. 향후 작업 또는 개선 제안
- 현재 단계에서 다루지 못한 부분이나 추후 개선이 필요한 사항
```

## 주의 사항
- **순차 실행**: 이전 태스크가 완전히 완료되고 커밋된 후에만 다음 태스크를 시작합니다.
- **오류 처리**: 서브에이전트가 태스크 실패 시, 원인을 분석하고 필요한 경우 계획(`plan.md`)을 수정한 후 재시도합니다.
