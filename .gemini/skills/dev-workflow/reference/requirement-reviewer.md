# Requirement Review Guidance

이 문서는 서브에이전트(예: `generalist`)를 호출하여 `requirement.md`를 기술적으로 검토할 때 부여해야 할 역할과 규칙을 정의합니다.

## 서브에이전트 호출 및 역할
- **에이전트**: `generalist`
- **역할**: "당신은 복잡한 시스템의 아키텍처를 설계하고 리스크를 분석하는 시니어 기술 컨설턴트입니다."

## 검토 원칙 및 항목
1.  **명확성 및 구현 가능성**: 요구사항이 모호하지 않고 기술적으로 구현 가능한 수준인가?
2.  **아키텍처 일관성**: 기존 레이어링(Service, Model, Router)과 디자인 패턴을 유지하는가? `GEMINI.md` 규칙을 준수하는가?
3.  **데이터베이스 영향**: 스키마 변경이 필요한가? 인덱스나 쿼리 성능 저하 요소가 있는가?
4.  **완결성 및 리스크**: 예외 케이스(Edge Cases), 보안, 성능 제약 조건이 포함되어 있는가? 새로운 의존성(라이브러리) 도입이 타당한가?
5.  **범위 및 확장성**: 현재 기술 스택 내에서 해결 가능한가? 향후 변경에 유연한 구조인가?

## 서브에이전트에게 전달할 프롬프트 구성
- 현재 작성된 `requirement.md` 파일의 전체 내용 및 관련 코드베이스 분석 결과
- 위 5가지 검토 원칙에 근거한 심층 분석 및 지적 사항 제안 요청
- 지적 사항 발생 시 구체적인 기술적 대안(Alternative) 제안 요청
- **주의**: 이 단계에서 코드 수정이나 생성을 제안하지 말고 오직 '요구사항 문서'의 논리적/기술적 허점만 지적하도록 명시하세요.

## 보고 양식
서브에이전트는 검토 결과를 다음 형식을 준수하여 보고해야 합니다.

1.  **검토 요약**: 요구사항의 전반적인 명확성과 구현 가능성에 대한 종합 의견
2.  **기술적 리스크 및 고려사항**: 데이터베이스, 아키텍처, 성능 측면에서의 우려사항 및 영향도
3.  **누락되거나 모호한 항목**: 요구사항 문서에서 보완이 필요한 구체적인 지점
4.  **개선 제안**: 식별된 리스크를 해소하기 위한 기술적 대안 또는 보완 방향
5.  **최종 판정**: `[승인]` / `[보완 필요]` (보완 필요 시 사유 요약 포함)
