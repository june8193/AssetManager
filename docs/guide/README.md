# AssetManager 기능 가이드 문서 규칙 (README.md)

이 문서는 **AssetManager** 프로젝트의 각 메뉴별 기능 가이드를 관리하는 가이드라인 및 설명서 홈입니다. 본 폴더 내의 가이드 문서는 지인이나 오픈소스 생태계(GitHub 등)에 프로젝트를 설명하고 기능을 직관적으로 보여주기 위해 작성되었습니다.

---

## 1. 가이드 문서의 목적
* **쉬운 기능 설명**: 자산 관리 시스템이 처음인 사용자나 외부 검토자에게 주요 특징과 핵심 UX를 시각적(스크린샷)으로 설명합니다.
* **일관된 문서 품질**: 새로운 기능이나 메뉴가 추가될 때 동일한 톤앤매너와 구조로 작성할 수 있도록 문서 양식을 정형화합니다.
* **개인정보 보호**: 실제 자산 데이터 대신 개발용 테스트 데이터(`src/dev_assets.db`) 환경에서 촬영한 화면을 활용하여 민감 정보 노출을 원천 차단합니다.

---

## 2. 가이드 디렉토리 구조

```text
docs/guide/
├── README.md               # [현재 문서] 작성 가이드라인 및 목차
├── dashboard.md            # 대시보드 (성과비교) 메뉴 설명
├── market_analysis.md      # 시장분석 메뉴 설명
├── watchlist.md            # 관심종목 메뉴 설명
├── ratio_check.md          # 비중 점검 및 비율계산기 설명
├── db_management.md        # DB 관리 (마스터 관리) 설명
├── snapshot_wizard.md      # DB 관리 (스냅샷 생성 마법사) 설명
├── api_connection.md       # API 연결 관리 설명
└── images/                 # 각 문서에 삽입될 1280x800 해상도 스크린샷 저장 폴더
```

---

## 3. 문서 작성 및 포맷 규칙

추후 신규 가이드 문서를 추가하거나 기존 가이드를 수정할 때는 다음 규칙을 엄격히 준수합니다.

### 3.1. 언어 및 작성 스타일
* **기본 언어**: 모든 문서 본문은 **한국어**로 작성합니다.
* **어조**: 정중하면서도 명확한 서술형 어투(예: "~합니다", "~할 수 있습니다")를 사용합니다.
* **가독성**: 텍스트만 나열하지 않고 불릿 포인트, 하이라이트 블록(Alert), 키보드 단축키나 강조 표기 등을 적극 활용합니다.

### 3.2. 스크린샷 촬영 규격
* **데이터 원천**: 절대 실제 자산 정보가 포함된 `assets.db` 환경에서 찍지 않고, `dev_assets.db`가 로드된 로컬 개발 서버(`uv run scripts/dev.py`) 환경에서 촬영합니다.
* **화면 해상도**: **1280 x 800** (가로 1280px, 세로 800px) 고정 데스크톱 뷰를 사용합니다.
* **이미지 저장**: `docs/guide/images/` 폴더 내에 소문자와 언더바(`_`) 조합의 직관적인 이름으로 저장합니다. (예: `dashboard.png`)
* **마크다운 연동**: 마크다운 파일에서는 상대 경로를 사용해 이미지를 삽입합니다.
  ```markdown
  ![대시보드 화면](./images/dashboard.png)
  ```

* **[기능명 2]**: 예시와 함께 입력값, 결과값에 대한 내용을 적습니다.

> [!CAUTION]

## 5. 신규 메뉴 가이드 추가 절차 (5단계)
1. **개발 서버 구동**: `uv run scripts/dev.py` 명령어로 로컬 테스트 환경을 켭니다.
2. **화면 캡처**: Playwright 브라우저 도구 등을 활용하여 `1280x800` 해상도로 해당 신규 메뉴 화면을 캡처한 뒤 `docs/guide/images/`에 적절한 이름으로 저장합니다.
3. **가이드 마크다운 생성**: 본 가이드라인의 `4. 기본 템플릿`을 복사하여 `docs/guide/` 내에 새 마크다운 파일을 생성합니다.
4. **목차 업데이트**: 본 `README.md` 문서의 `2. 가이드 디렉토리 구조` 목록에 새로 추가된 마크다운 파일을 링크합니다.
5. **검토 및 저장**: 상대경로 링크가 깨지지 않았는지 로컬 렌더러를 통해 확인한 후 Git 저장소에 커밋합니다.
