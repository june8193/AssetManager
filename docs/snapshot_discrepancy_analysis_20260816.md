### ② 불일치 발생 메커니즘 (8/1자 100만 원 입금의 스냅샷 누락)

1. **거래 내역 (카카오뱅크)**:
   * `2026-08-01`: DEPOSIT `+1,000,000원` (트랜잭션 ID: 204)
   * `2026-08-02`: WITHDRAW `-15,000,000원` (트랜잭션 ID: 206, 키움증권 이체)

2. **8/1 스냅샷 생성 시점**:
   * 8/1 스냅샷 생성 당시 카카오뱅크 잔고(`total_valuation`)는 8/1자 100만 원 입금이 반영되지 않은 `64,464,284원`으로 확정되었습니다.
   * `period_deposit`은 `-12,524,497원`으로 정상 집계되었으나 잔고가 100만 원 부족하여, 스냅샷 테이블의 기간수익 컬럼인 `total_profit`이 `-1,000,000원`으로 왜곡 기록되었습니다.

3. **8/16 스냅샷 집계 시점**:
   * 스냅샷 엔진의 기간 거래 집계 조건이 `transaction_date > '2026-08-01'`(초과)이므로, `2026-08-01` 날짜로 등록된 100만 원 입금은 8/16 스냅샷 집계에서도 제외되었습니다.
   * 8/2자의 `-15,000,000원` 출금만 집계되어 `period_deposit = -15,000,000원`으로 기록되었습니다.
   * 결과적으로 8/16 카카오뱅크 잔고(`50,464,284원`)에는 8/1의 100만 원 입금이 포함되어 있었기 때문에, 8/16 스냅샷의 기간수익(`total_profit`)이 `+1,000,000원`으로 왜곡 기록되었습니다.

4. **결과**:
   * 카카오 잔고는 100만 원 입금과 1,500만 원 출금으로 인해 실제로는 `64,464,284원` $\rightarrow$ `50,464,284원`으로 **1,400만 원만 감소**했습니다.
   * 하지만 8/1 기초 잔고가 100만 원 적게 잡혀 있어 대시보드 전체 자산 계산 시 이 100만 원이 수익으로 과대 계상되었습니다.

## 3. DB 수정 가이드

거래 일자를 변경하는 대신, 거래가 실제로 발생한 8/1자의 스냅샷 잔고를 바로잡고 왜곡되었던 카카오뱅크 기간수익(`total_profit`)을 0원으로 정상화합니다.

> [!NOTE]
> `account_snapshots` 테이블의 `total_profit` 컬럼은 레거시 명칭이며, 실제로는 **해당 스냅샷 기간의 기간수익(Period Profit)**을 저장합니다.

### 대상 레코드
* 테이블: `account_snapshots`
* 대상 1: `account_id = 13` (카카오뱅크) AND `snapshot_date = '2026-08-01'` (`id = 487`)
  * `total_valuation`: `64464284.0` $\rightarrow$ **`65464284.0`** (+1,000,000원)
  * `total_profit`: `-1000000.0` $\rightarrow$ **`0.0`**
* 대상 2: `account_id = 13` (카카오뱅크) AND `snapshot_date = '2026-08-16'` (`id = 499`)
  * `total_profit`: `1000000.0` $\rightarrow$ **`0.0`**

### 실행 SQL
```sql
-- 1) 8/1 카카오뱅크 스냅샷 잔고 100만원 증액 및 기간수익 0원 보정
UPDATE account_snapshots
SET total_valuation = 65464284.0,
    total_profit = 0.0
WHERE id = 487;

-- 2) 8/16 카카오뱅크 스냅샷 기간수익 0원 보정
UPDATE account_snapshots
SET total_profit = 0.0
WHERE id = 499;
```
