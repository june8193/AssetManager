# 05 — 실제 샘플 파일 E2E 통합 검증 및 최종 점검

**What to build:** 
개발 서버 환경(`uv run scripts/dev.py`, 격리 DB `dev_assets.db`)에서 사용자가 제공한 실제 현대카드 명세서(`hyundaicard_2608.html`) 및 카카오뱅크 거래내역(`카카오뱅크_거래내역_...xlsx`) 파일을 직접 업로드하여, 복호화 파싱 -> 프리뷰 검토 -> 덮어쓰기 등록 -> 소유주별 대시보드 지표 및 거래 테이블 반영까지 전 과정의 E2E 동작을 검증하고 스크린샷과 함께 최종 검증 보고서를 완성합니다.

**Blocked by:** 
- 04 — 지출 모니터링 대시보드(소유주 탭, KPI, 차트) 및 거래 원장 관리 화면

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 개발 서버(`uv run scripts/dev.py`)가 백그라운드 태스크로 정상 실행된다 (운영 DB 접근 금지).
- [ ] 브라우저 환경에서 `http://localhost:5173/expenses`에 접속하여 사이드바 및 대시보드 기본 상태를 확인한다.
- [ ] 실제 카카오뱅크 거래내역 엑셀 파일을 업로드하여 950811 비밀번호로 복호화 후, 프리뷰에서 '현대카드' 대금 출금건을 '통계 제외' 처리하고 DB에 등록한다.
- [ ] 실제 현대카드 명세서 HTML 파일을 업로드하여 복호화 후 거래 목록을 검토하고 DB에 등록한다.
- [ ] 동일한 현대카드 명세서를 다시 업로드했을 때 기존 데이터가 정상적으로 덮어쓰기되어 금액이 중복 합산되지 않는지 검증한다.
- [ ] 소유주 탭(장준) 및 카테고리 도넛 차트, 월별 바차트, 거래 테이블이 실제 데이터에 맞게 올바르게 표현되는지 확인한다.
- [ ] `screenshots/YYYYMMDD_HHMMSS_expense_monitoring/` 폴더에 주요 검증 스크린샷을 저장하고 개발 서버 프로세스를 안전하게 종료한다.
