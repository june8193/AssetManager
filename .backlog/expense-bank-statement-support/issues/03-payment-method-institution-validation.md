# 03 — 결제수단-명세서 금융기관 불일치 검증 및 오업로드 방지

**What to build:** 사용자가 업로드 시 선택한 결제수단의 금융기관(예: 국민은행)과 업로드된 파일의 감지 결과(예: 신한은행)가 불일치할 경우 400 Bad Request 에러를 반환하여 잘못된 결제수단 선택으로 인한 데이터 오염을 방지합니다.

**Blocked by:** 01 — 국민은행 암호화 PDF 명세서 파싱 및 업로드 프리뷰 파이프라인, 02 — 신한은행 다중 월 암호화 PDF 명세서 파싱 및 필터링 파이프라인

**Status:** ready-for-agent

- [ ] `POST /api/expenses/upload-preview` 요청 시 선택된 `PaymentMethod`의 `institution`과 파서가 감지한 금융기관명을 비교 검증한다.
- [ ] 금융기관명이 불일치하는 경우(예: 국민은행 결제수단 선택 후 신한은행 파일 업로드) 상태코드 `400 Bad Request`와 함께 직관적인 안내 메시지(예: '선택한 결제수단(국민은행)과 업로드된 명세서(신한은행)가 일치하지 않습니다.')를 반환한다.
- [ ] 금융기관명이 일치하는 경우(예: 국민은행 결제수단과 국민은행 명세서) 정상적으로 파싱 프리뷰 결과를 반환한다.
- [ ] 결제수단 기관 검증 단위/통합 테스트가 통과한다.
