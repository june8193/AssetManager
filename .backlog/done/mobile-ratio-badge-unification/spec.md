# 모바일 비중점검 상태 배지 판별 기준 단일화 명세서

Status: ready-for-agent

## Problem Statement

모바일 웹의 '비중 점검' 화면에서 채권 등 특정 카테고리의 하위 서브카테고리(예: 미국 장기채)를 확인할 때, 하나의 카드 안에 **'매수 필요'**와 **'매도 필요'** 뱃지가 동시에 표시되는 모순적인 현상이 발생하고 있습니다.

이 문제는 모바일 비중 카드 컴포넌트에서 상태 배지를 결정할 때 내부 비중 편차(`diffRatio`, %p)와 리밸런싱 필요 금액(`diffAmt`, 원) 두 가지 지표를 `||`(OR) 연산자로 결합하여 평가하기 때문에 발생합니다. 

계층형 포트폴리오(대분류 ➡️ 중분류 ➡️ 종목) 구조에서는 상위 대분류(채권)의 총 보유액이 목표치보다 크게 부족한 경우, 서브카테고리(미국 장기채)의 절대 금액은 목표치에 미달하여 **매수가 필요**한 상태가 됩니다. 그러나 동시에 대분류 내부에서의 상대적 비중은 목표치보다 높아 비중 편차 기준으로는 **매도(초과)** 상태로 판별될 수 있습니다. 

그 결과 두 조건이 동시에 충족되고, 화면 렌더링 또한 상호 배타적이지 않아 두 뱃지가 나란히 노출되어 사용자에게 심각한 혼란을 초래합니다.

## Solution

모바일 비중 카드의 상태 배지 판별 기준을 데스크톱 웹의 동작 방식 및 사용자의 실제 행동(Actionable Insight)과 완전히 일치하도록 **'리밸런싱 필요 금액' 단일 기준**으로 일원화합니다.

1. **상태 판별 기준 단일화**: 비중 편차(`diffRatio`) 조건을 배제하고, 실제 자금 투입/회수 액션을 결정하는 리밸런싱 필요 금액(`diffAmt`)만을 유일한 판별 척도로 사용합니다.
2. **명확한 임계값 적용**: 리밸런싱 필요 금액이 +1,000원 초과이면 **'매수 필요'**, -1,000원 미만이면 **'매도 필요'**, 그 사이의 미세 차이는 **'적정'**으로 명확히 분류합니다.
3. **상호 배타적 렌더링 보장**: UI 렌더링 시 단일 분기 구조를 적용하여 어떤 예외 상황에서도 하나의 카드에 단 1개의 상태 배지만 노출되도록 강제합니다.
4. **시각적 일관성 유지**: 상단 상태 배지, 하단 리밸런싱 조정 텍스트, 진행률 게이지 바 색상이 모두 단일화된 상태 기준에 따라 일관되게 반응하도록 정리합니다.

## User Stories

1. As a 모바일 자산 관리 사용자, I want to 서브카테고리 카드를 볼 때 '매수 필요' 또는 '매도 필요' 중 단 하나의 일관된 배지만 표시되기를 원한다, so that 모순된 정보 없이 포트폴리오를 조정할 수 있다.
2. As a 채권 투자자, I want to 채권 전체 자산이 부족하여 추가 매수가 필요한 경우 상위 비중과 무관하게 실제 투자해야 하는 방향인 '매수 필요' 배지를 확인하기를 원한다, so that 포트폴리오 목표에 맞게 자금을 올바르게 배분할 수 있다.
3. As a 모바일 사용자, I want to 상단 상태 배지의 의미가 카드 하단의 리밸런싱 조정 금액 안내 문구와 완벽히 일치하기를 원한다, so that 혼란 없이 직관적으로 현황을 파악할 수 있다.
4. As a 포트폴리오 관리자, I want to 리밸런싱 필요 금액이 1,000원 이내의 미세한 차이일 경우 '적정' 배지가 표시되기를 원한다, so that 사소한 잔액 차이로 인한 불필요한 매수/매도 압박을 받지 않을 수 있다.
5. As a 목표 비중 미설정 사용자, I want to 목표 비중이 없는 자산에 대해서는 기존과 동일하게 상태 배지가 노출되지 않기를 원한다, so that 목표 관리 자산과 자유 보유 자산을 명확히 구분할 수 있다.
6. As a 멀티 디바이스 사용자, I want to 데스크톱 웹의 리밸런싱 가이드와 모바일의 리밸런싱 배지가 동일한 계산 로직과 기준을 따르기를 원한다, so that 기기 간 데이터 해석의 불일치가 발생하지 않는다.
7. As a 모바일 사용자, I want to 서브카테고리뿐만 아니라 개별 종목 레벨에서도 상위 카테고리와의 편차 불일치로 인한 다중 배지 노출 오류가 발생하지 않기를 원한다, so that 모든 계층에서 신뢰할 수 있는 정보를 제공받을 수 있다.
8. As a 비중 점검 사용자, I want to 진행률 게이지 바의 색상 역시 단일화된 상태(초과/부족/적정)에 맞춰 일관되게 표시되기를 원한다, so that 시각적 인지와 텍스트 배지가 자연스럽게 조화를 이룰 수 있다.

## Implementation Decisions

- **상태 판별 단일 척도 채택**:
  - `isOver`와 `isUnder` 판별식에서 `diffRatio` 조건을 완전히 제거합니다.
  - 리밸런싱 필요 금액(`diffAmt`)만을 기준으로 삼아, 양수(+)이면 부족(매수 필요), 음수(-)이면 초과(매도 필요)로 판별합니다.
- **임계값(Threshold) 정책**:
  - 금융 데이터의 단수 차이 및 불필요한 잦은 알림을 방지하기 위해 절댓값 1,000원(`Math.abs(diffAmt) <= 1000`) 이내는 '적정'으로 간주합니다.
- **UI 렌더링 상호 배타성 강화**:
  - 독립적인 복수 `&&` 조건 렌더링을 폐지하고, `isBalanced` / `isUnder` / `isOver` 중 정확히 하나만 선택되는 단일 조건문 또는 삼항 연산자 형태로 배지를 렌더링합니다.
- **진행률 게이지 바 색상 연계**:
  - 게이지 바 하이라이트 색상 역시 단일화된 판별 결과(`isOver` ➡️ Amber, `isUnder` ➡️ Sky, `isBalanced` ➡️ Emerald)를 그대로 공유하여 텍스트 배지와 시각적 표현이 일치하도록 합니다.
- **하단 조정 금액 텍스트와의 정합성**:
  - 카드 하단의 `diffAmt > 0 ? '매수 필요' : '매도 필요'` 표기와 상단 뱃지가 완벽히 동일한 부호를 참조하게 되므로, 카드 내 상·하단 정보 불일치가 원천 해소됩니다.

## Testing Decisions

- **테스트 관점 및 원칙**:
  - 내부 구현 변수명이 아닌 컴포넌트의 외부 렌더링 결과(사용자 화면에 표시되는 배지 텍스트 및 그 배타성)를 검증합니다.
- **테스트 심(Seam)**:
  - 신규 seam을 생성하지 않고, 기존 모바일 비중 카드 컴포넌트의 단일 렌더링 인터페이스(`MobileRatioCard`)를 유일한 seam으로 활용합니다.
- **필수 검증 시나리오**:
  1. **상호 배타성(Negative Assertion) 검증**:
     - '매수 필요' 배지 노출 시 화면 전체에서 '매도 필요' 텍스트가 절대 존재하지 않아야 함을 검증합니다.
     - '매도 필요' 배지 노출 시 화면 전체에서 '매수 필요' 텍스트가 절대 존재하지 않아야 함을 검증합니다.
  2. **계층형 불일치 엣지 케이스 검증**:
     - 실제 문제 상황(채권 내 비중은 초과(+%p)이나 전체 기준 리밸런싱 금액은 부족(+원))의 데이터를 주입했을 때, '매도 필요'가 아닌 **'매수 필요'** 뱃지 1개만 단독으로 렌더링되는지 검증합니다.
  3. **임계값 내 적정 상태 검증**:
     - 리밸런싱 금액이 1,000원 이내(예: 500원, -300원, 0원)인 경우 '적정' 뱃지가 올바르게 노출되는지 검증합니다.
- **기존 테스트 참고(Prior Art)**:
  - 기존 `MobileRatioCard.test.jsx`의 Vitest + React Testing Library 테스트 구조와 렌더링 헬퍼를 그대로 계승합니다.
