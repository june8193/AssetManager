# 모바일 웹 '자산 조회' 계좌별 보유종목 내림차순 정렬 명세서

Status: resolved

## Problem Statement

현재 모바일 웹의 '자산 조회' 탭에서 계좌 카드를 터치하여 보유 종목 아코디언 드롭다운을 펼쳤을 때, 종목들이 평가금액 순서가 아닌 임의의 순서(DB 등록 순서 등)로 나열되어 있습니다. 
이로 인해 사용자가 해당 계좌에서 가장 비중이 크고 중요한 핵심 보유 자산이나 예수금을 한눈에 빠르게 파악하기 어렵고, 스크롤을 내려 일일이 찾아봐야 하는 불편함이 있습니다.

## Solution

모바일 웹 '자산 조회' 탭의 계좌별 아코디언 드롭다운 내 보유 종목 리스트를 **평가금액(KRW)이 큰 순서부터 아래로(내림차순)** 정렬하여 표시합니다.

1. **평가금액 기준 내림차순 정렬**: 예수금(현금 자산)을 포함한 모든 계좌 내 보유 자산에 대해 평가금액(`valuation_krw`)이 가장 큰 자산이 목록 최상단에 위치하도록 정렬합니다.
2. **2차 정렬 기준(타이브레이커) 적용**: 평가금액이 동일하거나 0원인 자산이 복수 개 존재하는 경우, 종목명(`name`)을 기준으로 가나다/알파벳 오름차순 정렬하여 일관된 순서를 보장합니다.
3. **실시간 시세 반영 시 정렬 유지**: 실시간 시세 새로고침 등으로 자산 평가액이 변동될 때에도 자동으로 내림차순 정렬 순서가 갱신되어 최신 중요도 순서를 항상 유지합니다.
4. **API 데이터 일관성 보장**: 대시보드 요약 데이터를 제공하는 백엔드 서비스 계층에서도 계좌별 종목 목록을 동일한 정렬 규칙으로 사전 정렬하여 전달합니다.

## User Stories

1. As a 모바일 자산 관리 사용자, I want to 계좌 아코디언을 펼쳤을 때 평가금액이 가장 큰 종목을 최상단에서 즉시 확인하기를 원한다, so that 해당 계좌의 핵심 주력 자산을 스크롤 없이 한눈에 파악할 수 있다.
2. As a 현금 비중을 관리하는 사용자, I want to 예수금(원화/외화)도 일반 종목과 함께 동일하게 평가금액 순서에 맞춰 나열되기를 원한다, so that 계좌 내에서 현금이 주식 등 다른 자산 대비 어느 정도 규모인지 직관적으로 비교할 수 있다.
3. As a 소액 분산 투자자, I want to 평가금액이 동일하거나 잔고가 0원인 여러 종목이 있을 때 종목명 가나다순으로 깔끔하게 정렬되기를 원한다, so that 예측 가능하고 정돈된 화면을 볼 수 있다.
4. As a 실시간 시장 모니터링 사용자, I want to 실시간 시세 새로고침을 실행했을 때 평가액 변동에 맞춰 종목 순서가 실시간으로 재정렬되기를 원한다, so that 급등락 후에도 항상 최상위에 가장 가치 있는 종목이 표시될 수 있다.
5. As a 개인정보 보호 모드 사용자, I want to 금액 마스킹 모드를 켠 상태에서도 평가금액 내림차순 정렬 구조가 깨지지 않고 그대로 유지되기를 원한다, so that 외부 환경에서도 종목 중요도 순서를 직관적으로 확인할 수 있다.
6. As a 다계좌 보유 사용자, I want to 각 계좌별로 독립적으로 보유 종목들이 각각의 평가금액 순으로 정렬되기를 원한다, so that 개별 계좌마다 포트폴리오 구성을 효율적으로 검토할 수 있다.

## Implementation Decisions

- **정렬 대상 및 우선순위**:
  - 특정 카테고리(예수금 등)를 별도 고정하지 않고, 계좌에 속한 전체 자산(`assets`)을 단일 리스트로 취급하여 평가금액 순으로 통합 정렬합니다.
  - 1차 기준: 평가금액(`valuation_krw`) 내림차순
  - 2차 기준: 종목명(`name`) 오름차순 (문자열 로케일 비교)
- **프론트엔드 렌더링 계층 최적화**:
  - 모바일 계좌 카드 컴포넌트 내부에서 메모이제이션을 통해 정렬된 자산 리스트를 계산하여 불필요한 재계산 렌더링을 방지합니다.
  - 원본 `assets` 배열을 직접 변조(mutate)하지 않고 불변성을 유지하며 얕은 복사 후 정렬합니다.
- **백엔드 대시보드 서비스 계층 사전 정렬**:
  - 대시보드 요약 응답을 생성하는 서비스 로직에서 계좌별 보유 종목 리스트를 반환하기 전에 동일한 1차/2차 정렬 로직을 적용하여 일관성을 제공합니다.

## Testing Decisions

- **좋은 테스트 원칙**:
  - 컴포넌트의 내부 상태나 정렬 알고리즘 구현 상세가 아닌, 실제 DOM에 렌더링되는 종목 텍스트 및 순서(사용자가 보는 외부 동작)를 검증합니다.
- **테스트 대상 모듈**:
  - 프론트엔드: 모바일 계좌 카드 컴포넌트 (Vitest + React Testing Library)
  - 백엔드: 대시보드 요약 서비스 API 테스트 (pytest)
- **주요 테스트 케이스**:
  1. 평가금액이 서로 다른 여러 종목(예: 주식 3,500만 원, 예수금 1,500만 원, 소액 주식 500만 원)이 주어졌을 때, 렌더링된 종목 목록이 금액이 큰 순서대로 배치되는지 검증
  2. 평가금액이 동일한 두 종목(예: '삼성전자' 1,000만 원, 'LG에너지솔루션' 1,000만 원)이 있을 때 종목명 오름차순('LG에너지솔루션' -> '삼성전자')으로 배치되는지 검증
  3. 백엔드 대시보드 요약 API 호출 시 반환되는 계좌별 `assets` 리스트가 평가금액 내림차순으로 정렬되어 있는지 검증
- **기존 참고 테스트 (Prior Art)**:
  - 프론트엔드: `src/components/mobile/MobileAccountCard.test.jsx`
  - 백엔드: `tests/test_dashboard.py`

## Out of Scope

- 모바일 화면에서 사용자가 직접 정렬 기준(예: 매입가순, 수익률순, 이름순 등)을 동적으로 변경하는 드롭다운/필터 UI 추가
- 데스크톱 DB 관리 탭의 자산 원본 테이블 정렬 방식 변경
- 보유 종목 추가, 수정, 삭제 등의 편집(CUD) 기능 (모바일 자산 조회의 Read-Only 원칙 유지)

## Further Notes

- 모바일 UI 특성상 작은 화면에서 빠른 인지가 가장 중요하므로, 이번 내림차순 정렬 적용으로 주요 보유 자산에 대한 접근성이 대폭 향상됩니다.
- 향후 거래내역 탭이나 다른 모바일 화면에서도 일관된 정렬 경험을 제공할 수 있습니다.
