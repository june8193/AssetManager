# 모바일 웹 비중 점검 탭 사용성 및 리밸런싱 표시 개선 명세서

Status: resolved

## Problem Statement

현재 모바일 웹의 '비중 점검' 화면은 데스크톱 화면의 계산 모델을 그대로 가져와 모바일 환경에 적합하지 않은 불필요한 요소와 오해를 일으키는 정보들이 노출되고 있습니다.

1. **불필요한 시뮬레이션 기능**: 모바일 환경에서는 추가 투자금 증액 시뮬레이션(100만, 500만 등)을 활용할 일이 적고 공간만 차지합니다.
2. **혼란을 주는 요약 지표**: 상단 요약 배너에 '현재 총 자산'과 함께 '목표 총 자산'이 별도로 표시되어 정보가 과다합니다.
3. **목표 미설정 자산의 과도한 경고**: 목표 비중이 별도로 설정되지 않아 0%로 저장된 자산들(개별 주식 등)이 전체 자산 규모만큼 '초과' 상태 배지와 매도 금액으로 표시되어 사용자에게 불필요한 혼란과 불안감을 줍니다.
4. **모호한 상태 명칭**: '초과', '추가 매수'라는 명칭보다 포트폴리오 리밸런싱 행동 관점에서 '매도 필요', '매수 필요'가 더 직관적입니다.
5. **종목 식별의 불편함**: 주식 자산이 종목명이 아닌 숫자 티커/종목코드로 표시되어 어떤 자산인지 한눈에 알아보기 어렵습니다.

## Solution

모바일 사용자 경험에 최적화되도록 '비중 점검' 탭을 간결하고 직관적으로 개편합니다.

1. **시뮬레이션 UI 및 상태 제거**: 모바일 화면에서 추가 투자금 시뮬레이션 관련 UI(칩 버튼 등)와 로직을 제거하여 뷰 공간을 확보합니다.
2. **요약 정보 단일화 및 간소화**: '목표 총 자산' 항목을 제거하고 '현재 총 자산'을 단일 메인 지표로 강조하며, 리밸런싱이 필요한 경우 '리밸런싱 규모'로 단일화된 총액을 간결하게 안내합니다.
3. **목표 미설정 자산 예외 처리**: 목표 비중이 0%이거나 미설정된 자산에 대해서는 상태 배지('매도 필요', '매수 필요', '적정'), 편차(%p), 리밸런싱 조정 금액을 숨기고 현재 평가액과 비중만 깔끔하게 표시합니다.
4. **직관적인 상태 명칭 적용**: 기존 상태명인 '초과'를 **'매도 필요'**, '추가 매수'를 **'매수 필요'**로 변경하여 행동 중심의 명확한 가이드를 제공합니다.
5. **종목명 메인 표시 및 티커 병기**: 자산 카드에 종목명을 메인 볼드로 표시하고, 티커(종목코드)는 옆에 서브로 병기(예: 삼성전자 (005930), 애플 (AAPL))하여 자산 식별성을 극대화합니다.

## User Stories

1. As a 모바일 자산 관리 사용자, I want to 모바일 비중 점검 화면에서 불필요한 투자금 시뮬레이터 없이 깔끔한 뷰를 볼 수 있기를 원한다, so that 스크롤 부담 없이 한눈에 포트폴리오 비중을 파악할 수 있다.
2. As a 모바일 자산 관리 사용자, I want to 상단 요약 배너에서 목표 총 자산 대신 현재 총 자산과 리밸런싱 필요 규모를 직관적으로 확인할 수 있기를 원한다, so that 현재 내 포트폴리오의 조정 규모를 즉각적으로 인지할 수 있다.
3. As a 개별 주식 투자자, I want to 목표 비중을 설정하지 않은 개별 주식 항목들에 대해 불필요한 '초과' 배지나 전액 매도 경고가 뜨지 않기를 원한다, so that 실제 목표를 관리하는 자산군과 자유롭게 보유하는 자산을 혼동 없이 구분할 수 있다.
4. As a 포트폴리오 리밸런싱 사용자, I want to 자산별 상태가 '초과'/'추가 매수' 대신 '매도 필요'/'매수 필요'로 표시되기를 원한다, so that 어떤 자산을 팔고 어떤 자산을 사야 하는지 명확히 이해할 수 있다.
5. As a 모바일 사용자, I want to 주식 종목을 볼 때 티커 번호(예: 005930) 대신 한글/영문 종목명(예: 삼성전자)과 티커가 함께 표시되기를 원한다, so that 내가 보유한 종목이 무엇인지 즉시 식별할 수 있다.
6. As a 모바일 사용자, I want to 목표 비중이 정상적으로 설정된 자산군(주식, 채권, 현금 등)에 대해서는 기존과 같이 정교한 비중 편차(%p)와 목표 비중 게이지 바를 확인할 수 있기를 원한다, so that 자산 배분 원칙을 철저히 준수할 수 있다.
7. As a 보안/프라이버시 중심 사용자, I want to 마스킹 모드가 활성화되었을 때 개편된 총 자산 및 리밸런싱 규모 금액도 정상적으로 마스킹(***) 처리되기를 원한다, so that 외부 환경에서도 안전하게 비중 점검 화면을 열람할 수 있다.
8. As a 반응형 웹 사용자, I want to 실시간 새로고침 버튼을 눌렀을 때 최신 시세가 반영된 비중 현황이 토스트 메시지와 함께 즉각 갱신되기를 원한다, so that 실시간 시장 변화에 맞춘 리밸런싱 계획을 세울 수 있다.

## Implementation Decisions

- **시뮬레이션 로직 분리 및 제거**: 모바일 비중 점검 화면에서는 추가 투자금(`additionalCash`) 상태 및 관련 핸들러를 완전히 제거하고, 기본 자산 계층 데이터를 기반으로 리밸런싱 결과를 렌더링합니다.
- **포트폴리오 비중 요약 배너 레이아웃 개편**:
  - 목표 총 자산 지표를 배너에서 제거하고 현재 총 자산 단일 포커스 뷰를 구성합니다.
  - 리밸런싱 조정 요약은 '매수 필요 +X원', '매도 필요 -X원' 대신 '리밸런싱 규모: X원' 형태로 단일화하여 제공합니다.
- **목표 비중 미설정 판별 기준 (`hasTarget`)**:
  - `target_percentage`가 정의되어 있고 0보다 큰 경우(`target_percentage > 0`)에만 목표가 설정된 것으로 판별합니다.
  - `hasTarget`이 거짓인 경우:
    - 상태 배지('매도 필요', '매수 필요', '적정') 미노출
    - 편차(%p) 및 리밸런싱 필요 금액 영역 미노출
    - 목표 비중 표시 영역은 '-' 또는 공란 처리
    - 비중 진행률 바는 중립적인 색상으로 현재 비중만 시각화
- **상태 배지 및 조정 텍스트 변경**:
  - `isUnder` (목표치 미달): 배지 텍스트 `매수 필요` (Sky 테마)
  - `isOver` (목표치 초과): 배지 텍스트 `매도 필요` (Amber 테마)
  - `isBalanced` (적정 범위): 배지 텍스트 `적정` (Emerald 테마)
  - 카드 하단 조정 필요 텍스트: `diffAmt > 0 ? '매수 필요' : '매도 필요'`
- **종목명 및 티커 표기 규칙**:
  - 주식 레벨 아이템 표시 시 자산 이름(`name`)을 우선 표기합니다.
  - 티커(`ticker`)가 존재하고 종목명과 다른 경우 메인 종목명 옆에 `(티커)` 형태로 병기합니다 (예: `애플 (AAPL)`).
  - 종목명이 없거나 동일한 경우 중복 없이 단일 표기합니다.

## Testing Decisions

- **테스트 기준**: 내부 구현 상세가 아닌 사용자 관점의 렌더링 동작(종목명 노출, 배지 텍스트, 목표 미설정 시 UI 요소 숨김, 마스킹 동작 등)을 테스트합니다.
- **테스트 모듈**:
  - 모바일 비중 점검 페이지 컴포넌트 단위 테스트
  - 모바일 비중 카드 컴포넌트 단위 테스트
- **주요 테스트 케이스**:
  1. 목표 비중이 0%인 종목에 대해 '초과', '매도 필요', '매수 필요' 배지가 노출되지 않는지 검증
  2. 목표 비중이 설정된 자산군에 대해 '매도 필요' 및 '매수 필요' 배지와 금액이 올바르게 노출되는지 검증
  3. 종목 항목 렌더링 시 티커 번호만이 아닌 종목명(예: '애플', '삼성전자')과 병기 티커가 올바르게 렌더링되는지 검증
  4. 상단 요약 배너에서 '목표 총 자산'이 제거되고 '현재 총 자산' 및 '리밸런싱 규모'가 올바르게 렌더링되는지 검증
  5. 추가 투자금 시뮬레이션 버튼들이 화면에 나타나지 않는지 검증
  6. 마스킹 모드 활성화 시 총 자산 및 리밸런싱 금액이 올바르게 마스킹되는지 검증
- **기존 참고 테스트**: 기존 모바일 컴포넌트 테스트 스위트(`MobileRatioCard.test.jsx`, `MobileRatiosPage.test.jsx`)의 Vitest + React Testing Library 패턴을 준용합니다.

## Out of Scope

- 데스크톱 버전의 '비중 점검'(`RatioCheckPage.jsx`) 페이지 수정 (데스크톱의 시뮬레이터 및 계산기 기능은 기존 유지)
- 백엔드 DB 스키마 변경 또는 신규 API 엔드포인트 개발 (기존 `hierarchy` API 응답 데이터 활용)
- 비중 점검 화면 내에서의 목표 비중 수정/저장 기능 (모바일은 Read-Only 원칙 유지)

## Further Notes

- 모바일 비중 점검 화면은 데스크톱보다 직관적이고 가독성이 높아야 하므로, 간결한 레이아웃과 불필요한 시각적 소음 제거에 중점을 둡니다.
- 추후 모바일 전용 자산 상세 모달이 추가될 경우 동일한 종목명 및 상태 명칭 규칙을 공유합니다.
