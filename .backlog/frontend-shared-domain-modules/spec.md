# Spec: 프론트엔드 데스크톱·모바일 공유 도메인 모듈 심화

Status: ready-for-agent

## Problem Statement (문제 정의)

데스크톱 웹 페이지와 모바일 PWA 화면이 동일한 도메인 개념(시장 지수·VIX, 벤치마크, 내재 변동성 리스크, 지출 원장, 자산 비중·보유자산)을 각자 별도로 구현하면서 심각한 규칙 드리프트와 동작 결함이 발생하고 있다. 대표적으로 VIX 4단계 기준이 데스크톱(`20/30/40`)과 모바일(`20/25/30`)에서 서로 다르게 표시되며, 모바일 지출 초기 진입 시 상단 KPI는 당월을 보여주면서 하단 거래 리스트는 전체 기간을 노출하는 정합성 불일치가 발생한다. 또한 모바일이 존재하지 않는 `/api/market/benchmark` 엔드포인트를 먼저 호출해 실패 왕복을 일으키거나, `setTimeout(300)` 후 무조건 성공 토스트를 띄우고, 거대 데스크톱 뷰 파일에서 함수를 역참조하며, `MobileAssetsPage` 진입 1회에 7개의 과잉 API 요청을 발생시키고 있다.

## Solution (해결 방안)

뷰포트(데스크톱·모바일)에 무관한 깊은 프론트엔드 도메인 모듈들을 세워 시황·VIX·벤치마크 비교, 리스크 진단 파생 지표, 지출 기간 동기화·페이징, 3계층 비중 리밸런싱 및 보유자산 슬라이스를 단일 인터페이스 뒤에 캡슐화한다. 데스크톱과 모바일 뷰는 레이아웃·시각 밀도만 담당하는 얇은 시각 어댑터로 전환하여 뷰 간 역참조와 모든 도메인 불일치를 제거한다.

## User Stories (사용자 스토리)

1. As an 모바일·데스크톱 사용자, I want VIX 지수 리스크 등급과 차트 기준선이 모든 화면에서 동일한 기준을 따르기를, so that 같은 날 PC와 모바일에서 서로 다른 시장 위험 진단을 받지 않는다.
2. As an 모바일 지출 사용자, I want 지출 화면 최초 진입 시 상단 KPI 요약과 하단 거래 내역이 동일한 기준월 범위로 조회되기를, so that 당월 요약 아래에 과거 월 거래가 섞여 보이지 않는다.
3. As an 모바일 사용자, I want 새로고침 시 하위 데이터 요청이 실제로 완료·성공했을 때만 완료 토스트가 뜨고 실패 시 오류 피드백이 표시되기를, so that 가짜 성공 알림에 속지 않는다.
4. As an 프론트엔드 개발자, I want 모바일 모듈이 거대 데스크톱 뷰 파일을 import하지 않고 공유 도메인 모듈만 바라보기를, so that 한쪽 화면 수정이 다른 쪽 화면의 불필요한 번들·의존성 깨짐을 유발하지 않는다.

## Implementation Decisions (구현 결정사항)

- **시장 지수·VIX·벤치마크 공유 모듈**: 4대 지수 메타·별칭 레지스트리, 단일 VIX 4단계 판정 기준, 기간 코드→날짜 범위 변환, 극단값 추출, 정규화 수익률 기반 MDD 계산, 단일 `/api/benchmark` 조회 및 실제 Promise 기반 새로고침 완료 반환을 뷰포트 독립 모듈로 통합한다(미사용 관심종목 상태 및 유령 엔드포인트 폴백 제거).
- **리스크 진단 공유 모듈**: 변동성 상태 배지, 스펙트럼 게이지 스케일, 액셀 Top 3, 완충 자산 필터, 현금 상단 고정 정렬, 차트 시계열 변환, 시뮬레이션 연산을 단일 도메인 모듈로 통합한다.
- **지출·비중·보유자산 공유 모듈**: 최근 24개월 목록·프리셋 역산·초기 기준월 확정 후 원장 조회·인라인 변경 시 통계 동기화를 단일 지출 도메인 모듈로 통합한다. 또한 3계층 비중 리밸런싱·100% 검증·평탄화 및 자산 추이 시계열 상태를 데스크톱 페이지에서 독립시키고, 보유자산 현황 전용 슬라이스를 분리해 모바일 7중 과잉 페칭을 해소한다.

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 뷰포트 독립 도메인 모듈의 파생 계산·기간 동기화·Promise 기반 새로고침 불변식을 검증하고, 데스크톱·모바일 페이지에서 동일한 도메인 결과가 렌더링되는지 확인한다.
- **사전 합의된 테스트 심 (Pre-agreed Seams)**:
  - 뷰포트 독립 도메인 모듈(훅·순수 파생 엔진) 인터페이스 + 계약 검증 Fake HTTP 어댑터: **Catches** VIX 임계값 불일치, 초기 지출 기준월 누락, Promise 기반 새로고침 오류 처리, 3계층 리밸런싱 합계 불변식 / **Misses** 실제 모바일 브라우저 CSS 레이아웃
  - 데스크톱·모바일 페이지 렌더링 인터페이스(React Testing Library): **Catches** 뷰포트별 상태 바인딩 누락 및 인터랙션 회귀 / **Misses** 스크롤·터치 제스처
- **참고할 기존 테스트 패턴**: `src/frontend/src/pages/mobile/MobileExpensesPage.test.jsx`, `src/frontend/src/pages/RatioCheckPage.test.jsx`, `src/frontend/src/pages/PerformanceAnalysisPage.test.jsx`.

## Out of Scope (범위 제외 사항)

- 원장 거래 행 편집기(`TransactionsTab`)와 스냅샷 위저드 상태 머신 심화(별도 피처 `frontend-transport-and-state-machines`에서 다룸).
- 모바일 UI 시각 디자인 전면 개편.

## Further Notes (기타 참고사항)

- 3개 티켓 모두 선행 블로커가 없어 병렬로 진행 가능하나, 공통 HTTP 어댑터 정리는 `frontend-transport-and-state-machines`와 보조를 맞추면 좋다.
