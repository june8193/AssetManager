# 03 — 미분류 거래 커밋 방지 및 원장 저장 유효성 검증

**What to build:**
명세서 업로드 미리보기에서 통계 반영 대상 거래 중 카테고리가 '미분류'인 거래가 1건이라도 남아있으면 '확정 및 저장' 버튼을 비활성화하고 사용자에게 미분류 건수를 명확히 알립니다. 백엔드 커밋 API에서도 미분류 항목이 포함되어 있으면 `400 Bad Request` 에러를 반환하여 잘못된 원장 저장을 차단하고, 통계 제외 건은 카테고리 없이도 저장을 허용합니다.

**Blocked by:** 02 — 명세서 업로드 미리보기 수동 검토 전환 및 통계 제외 연동

**Status:** resolved

- [x] 업로드 미리보기 모달에서 통계 반영 거래 중 카테고리가 선택되지 않은 건수를 실시간 집계하여, 미분류 건수가 1건 이상이면 '확정 및 저장' 버튼이 비활성화(`disabled`)된다.
- [x] 미분류 거래가 존재할 때 "미분류된 거래가 N건 있습니다. 모든 유효 지출에 카테고리를 지정해야 저장할 수 있습니다." 경고 배너가 표시된다.
- [x] 통계 제외(`is_excluded=True`)로 체크된 거래는 카테고리가 지정되지 않아도 유효한 것으로 인정되어 저장 차단 대상에서 제외된다.
- [x] 모든 유효 지출에 카테고리가 지정되면 '확정 및 저장' 버튼이 활성화되고 정상 저장 요청이 전송된다.
- [x] 백엔드 커밋 API(`POST /api/expenses/commit`)에서 통계 반영 거래 중 `category_id`가 누락된 항목이 있으면 `400 Bad Request` 에러를 발생시키며 저장을 거부한다.
- [x] 관련 백엔드 API 테스트 및 프론트엔드 업로드 모달 검증 테스트가 통과한다.
